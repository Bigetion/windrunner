FOUC Prevention Strategies

The built-in FOUCManager prevents flash of unstyled content by hiding elements until Windrunner has finished its first compilation scan.

Strategy: opacity

Hides with opacity:0, fades in with CSS transition

Waiting...

Configuration

fouc: {
  strategy: "opacity",
  duration: 300,
  selector: "#my-app"
}

How it works

  1. 1. Sets opacity: 0 on target before scan
  2. 2. Windrunner compiles and injects all CSS rules
  3. 3. Double rAF ensures browser has painted
  4. 4. Sets opacity: 1 with smooth transition

Strategy: visibility

Hides with visibility:hidden, reveals instantly

Waiting...

Configuration

fouc: {
  strategy: "visibility",
  duration: 0,
  selector: "#my-app"
}

How it works

  1. 1. Sets visibility: hidden on target
  2. 2. Layout is preserved (no content shift)
  3. 3. After scan completes, sets visibility: visible
  4. 4. Instant reveal — no transition delay

Strategy: none

No FOUC prevention — content shows immediately

Waiting...

Configuration

fouc: {
  strategy: "none"
}

// Or simply omit the fouc option:
windrunner({ autoStart: true })

When to use

  • • You have your own FOUC handling (like the v1 pattern)
  • • Server-rendered pages with critical CSS already inlined
  • • Development/prototyping where flash is acceptable
  • • Pages where content above the fold is minimal

Strategy Comparison

Strategy Layout Preserved Smooth Transition CLS Impact Best For
opacity Yes Yes (configurable) None Most applications
visibility Yes No (instant) None When instant reveal preferred
none N/A N/A Possible SSR / custom FOUC handling
